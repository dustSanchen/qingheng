# 16 · 多模型协作剧本（视觉风格优化）

> 用途：把「交给一个模型从头做到尾」的任务卡，拆成 4 道工序，每道工序交给最擅长的模型，
> 工序之间只传递**文件产物**，不传递口头上下文。
> 适用任务：轻衡视觉风格优化（1.1.91 起）。

## 0. 为什么拆

一张任务卡里混着四种性质不同的工作，它们的失败模式完全不同：

| 工作性质 | 需要的能力 | 单模型全做的后果 |
|---|---|---|
| 看截图判断"哪里不像品牌" | 视觉/多模态 | 纯文本模型只能凭描述猜，诊断必然是套话 |
| 写规格（信息设计决策） | 审美判断 + 取舍表达 | 实现型模型容易直接跳到改代码 |
| 改 fragment + CSS + 跑测试 | 工具调用稳定性、约束遵守 | 审美型模型容易改跑偏、破坏既有维度 |
| 文案语气校准 | 中文语感 | 外语模型写出来像翻译腔 |

## 1. 分工表

| 工序 | 模型 | 为什么是它 | 产物 |
|---|---|---|---|
| ① 视觉诊断 | `gemini-4-argon` | 22 个模型里多模态最强，能真读截图 | `docs/design/16-audit-visual.md` |
| ② 规格与取舍 | `claude-haiku-5.5` | Claude 谱系的审美判断，擅长写"为什么不选另一个" | 追加到同一份 md 的「规格」节 |
| ③ 落地实现 | `gpt-6-luna` | catalog 自带前端设计规范，工具调用最稳，窗口 400k | 代码改动 + 测试结果 |
| ④ 评审挑刺 | `claude-haiku-5.5` | 同一模型换角色复查，能指出"看起来廉价" | 评审意见（≤8 条） |
| ⑤ 文案校准 | `qwen3.8-max` | 中文语感最好 | 文案替换清单 |
| 备选：大重构 | `kimi-k3.1-pro` / `qwen3.8-max` | 逻辑更强，窗口 131k | — |
| 备选：批量小改 | `kimi-k2.7-code` | $0.95/$4.00、月额度 $60，最便宜 | — |

**关键约束：同一个文件同一时间只能有一个模型在改。** 工序 ①②⑤ 只写文档，工序 ③ 独占代码。

## 2. 交接物（唯一可信来源）

```
docs/design/16-audit-visual.md     ← ① 写，② 追加，③ 读
build/visual-before/*.png          ← ① 产出（或复用已有截图）
git HEAD                            ← ③ 的基线，每次改完可回滚
tools/test-all.mjs                  ← 每道工序的硬门槛（56/56）
```

## 3. 可直接粘贴的提示词

### ① 视觉诊断（gemini-4-argon）

```
你是视觉设计评审，不是工程师。仓库 D:\AI\health-android，版本 1.1.91。

只做一件事：看截图，指出"为什么它看起来像被整理过的表单，而不像一个有主张的品牌"。

截图：build/ 下最新的今日页、趋势页、记录页各一张（没有就先运行
node tools/device.mjs shot build/visual-before/today.png，再切页各截一张）。
如果看不到图，直接回答"我没有收到截图"，不要凭想象写。

已经成立的风格（不要建议推翻）：
纸感底 + 衬线标题 + 苔绿强调；两套皮肤共用语义色；字号 13/15/17/20/26/32；
圆角 8/12/20；线语言三档（--line 分区 / --line-strong 控件 3.36:1 / focus-visible）；
图像符号只有三个：叶、天平、环（24 网格、1.5px 圆头、单色）。

输出到 docs/design/16-audit-visual.md，格式：
判断: <一句话，说清最伤的 1 个问题>
证据: <截图里具体位置 + 你看到的像素级现象，例如"卡片圆角 20 与内部控件圆角 12 形成双重轮廓">
候补问题: <最多 5 条，每条一行，按严重度排序>
不要写解决方案，那是下一道工序的事。
```

### ② 规格与取舍（claude-haiku-5.5）

```
你是产品设计规格作者。读 docs/design/16-audit-visual.md，把它变成可实现的规格。

只写规格，不改代码。范围限定三件：
1) 图形语言：空态用叶 40px、加载用环 20px 匀速、完成用叶 24px + --ok；
   并列出「什么时候不用符号」的三条禁用场景。
2) 趋势图：点按取数（44dp 热区）、目标区间带（12% 透明）、空态骨架。
3) 今日页视线顺序：现状数字/按钮/解释文字挤在一张卡，给出层级重排。

每条规格 ≤3 行，必须包含：改哪个文件、改什么参数、验收怎么判断。
每个决策配一句"被放弃的替代方案 + 为什么放弃"。

禁止：重新定义已有维度（能量环绿环始终满圈表示 0–100%，超出用棕红从同一起点覆盖）；
禁止：一段里出现两个主数字；禁止：解释文字与主行动同屏竞争。

追加到 docs/design/16-audit-visual.md 的「规格」节。
最后一行写：SPEC DONE, N 条。
```

### ③ 落地实现（gpt-6-luna）

```
你是这个仓库的工程师。先读 docs/design/16-audit-visual.md 的「规格」节，只实现那一节写的东西。

硬规则（违反任何一条都算失败）：
1. 不手改 app/src/main/assets/app.js，它是 tools\assemble-app.ps1 从 app/src/fragments/* 拼出来的；
   改片段后必须跑 assemble。
2. 账本改动只能写在 [data-skin="ledger"] 作用域；两套皮肤改一处必须同时改另一处。
3. 新增颜色令牌要登记 docs/design/02-tokens.md，且纸感与账本令牌集必须相等，缺一个测试会红。
4. 改测试断言前先在 docs/design/03-global-changes.md §5.1 登记。
5. 同一目标连续两次测试仍红 → 停止，输出 BLOCKED: <根因> + <需要什么>。

流程：改片段 → tools\assemble-app.ps1 → node tools/test-all.mjs（必须 56/56）
→ tools\dev-loop.ps1 -Version 1.1.92 -VersionCode 192 -SkipBackup 装机 → 截图 before/after。

交付固定格式：
判断: <现状哪里不对，一句>
改动: <文件:行 / 设计参数>
理由: <为什么更好，可验证>
外加：3 组 before/after 截图路径；一个"没做什么及原因"；测试结果。
```

### ④ 评审挑刺（claude-haiku-5.5）

```
你是交付前的评审，不是作者。看这三样：改动列表、before/after 截图、
node tools/aesthetic-audit.mjs 的输出。

只回答一个问题：这版比上一版更像"有主张的品牌"了吗？

输出 ≤8 条意见，每条必须是可执行的判断，例如：
"卡片圆角 20 与内部控件 12 形成双重轮廓，建议统一为 16" ✅
"整体感觉还可以再精致一点" ❌（太虚，不要写）

如果确实没有值得改的，直接说"无阻塞意见"，不要凑数。
不要重新设计，只指出问题。
```

### ⑤ 文案校准（qwen3.8-max）

```
你是中文产品文案。仓库 D:\AI\health-android，只改文案，不改结构与样式。

范围：docs/design/16-audit-visual.md 里标记需要改文案的条目，以及你顺带发现的生硬表达。
逐条给：原文 → 改后 → 一句理由。

硬约束：不写「加油」「坚持！」；不出现第三方品牌名；不诊断、不开处方；
缺口类数字给方向即可（例："还差 29 g，下一餐先吃蛋白质"），不要换算成食材克数。
热量下限 2,000 kcal 是底线，不能建议低于它。

输出一张替换清单，格式：文件:行 | 原文 | 改后 | 理由。
```

## 4. 交接检查（每道工序结束都跑）

```powershell
cd D:\AI\health-android
node tools/preflight.mjs          # 路径/设备/测试/版本一致
git status --short                # 确认只有本工序该改的文件
node tools/test-all.mjs           # 必须 56/56
```

任何一项不对 → 停下，把问题写回 `16-audit-visual.md`，不要带着脏状态进下一道工序。

## 5. 成本参考（按 Go 价目，每百万 token）

| 模型 | 入/出 | 这道工序大概花多少 |
|---|---|---|
| gemini-4-argon | 2 / 10 | 看 3 张图 ≈ $0.02 |
| claude-haiku-5.5 | 0.10 / 0.50 | 写规格 ≈ $0.005 |
| gpt-6-luna | 0.10 / 0.50 | 实现 + 多轮测试 ≈ $0.05 |
| qwen3.8-max | 2 / 6 | 文案 ≈ $0.01 |

一轮完整流程大约几分钱，真正的成本是你的审阅时间——所以每道工序都要落到文件，方便你只读最终产物。

## 6. 什么时候不要拆

- 改动小于一行 CSS、或只是改个文案：直接一个模型做完，拆了反而多三次交接。
- 你已经明确知道要改成什么：直接给 gpt-6-luna 下指令，跳过 ①②。
- 任务涉及跨文件重构：用 kimi-k3.1-pro 一次做完，拆开会让风格断层。
