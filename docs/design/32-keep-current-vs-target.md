# 轻衡 × Keep：现状对照与分阶段优化方案

> 文件关系：本文件负责“Keep 原则 ↔ 轻衡现状”的判断；
> `30-deepseek-optimization-checklist.md` 是逐项任务源；
> `31-keep-phased-plan.md` 是阶段执行与版本记录。
>
> 当前基线：`1.4.83 / 483`，93 项测试。

## 结论先行

轻衡已有“目标测算 → 记录 → 本地建议 → 今日训练执行 → 趋势/周回看”的骨架。
继续借鉴 Keep 的重点不是增加课程或聊天，而是把已有能力收束成：

**记住目标与偏好 → 今天下一步 → 一键进入执行 → 完成后回流建议 → 每周诚实复盘。**

## 对照

| Keep 的有效做法 | 轻衡现状 | 判断 |
|---|---|---|
| 打开就知道今天做什么 | 今日能量、时段提示、单一行动、训练快捷入口 | 已补齐；行动卡复用现有组件，不新增页面 |
| 计划能直接执行 | 周计划、AI 排今天、逐组执行、休息计时、顺延 | 保留现有执行链 |
| 区分计划、休息、实际完成 | `trainingStateFor` 三态；显式休息入口 | 已补齐；休息不再被算作漏练 |
| 建议连到动作 | `actions` 文本 + 可选 `actionItems` 白名单 | 已补齐；只打开表单，不直接写库 |
| 记住偏好且可管理 | 偏好在「外观与偏好」内；对象数组存放来源/时间/scope；可编辑删除 | 已补齐；旧字符串/旧备份迁移 |
| 记录后给反馈 | 本地/AI 建议、指纹失效、快捷记录 | 已具备；不自动追加收费请求 |
| 每周复盘 | 原生日/周通知 + 趋势页本地周回看 | 已补应用内本地卡；数据不足不伪造对比 |
| 自然语言记一餐 | 现有文字/照片估算；P1-C 餐食草稿交接 | 已补齐；必须经过原有预览确认 |
| 餐食估算 | 精确食品名 + 克重/标准份量/区间中值先查本地 USDA 库；未知或估份量交给模型 | 1.4.79–83 本地优先，预览标明来源 |
| 全站视觉 | 1.4.79 页眉/分段/趋势/空态/问答视觉层；360/390 关键页截图 | 已做一轮，不等于逐页美术审计 |
| 会员/课程/社区/排行榜 | 不做 | 明确不做 |

## 关键设计边界

- 训练计划/勾选/实际动作是三个概念；不能用一个布尔值互相冒充。
- 偏好对象数组是唯一权威；`readPreferences()` 只向提示词交 text，界面用对象行。
- 建议按钮只做跳转和字段预填；保存仍走现有表单、预览和撤销。
- 周回看只用真实记录，不把缺失当没做，不诊断、不评分。
- 不新增第六个一级页面，不复制 Keep 品牌、课程或会员体系。

## 仍缺或不承诺

- 全站视觉重设计、逐页美术审计：未完成。
- 餐食热量/营养算法改版：未做，继续沿用现有食物模型、锚点、包装食品和用油规则。
- 餐食草稿只交接到现有估算表单；不会自动估算或自动保存。
- 320/360/390 与夜间只核验关键页，不等于每页全量审计。
