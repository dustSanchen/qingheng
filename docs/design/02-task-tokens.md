# 阶段 2 任务卡 · 令牌收敛

先读 `docs/design/00-brief.md` 与 `docs/design/01-audit.md`。
阶段 1 的审计结论必须被本阶段覆盖——每一条审计问题，都要能对应到某个 token 或某条规则。

---

## 本次任务

给出表格：token 名 | 现值(纸感/账本) | 建议值 | 理由 | 影响组件。
必须覆盖：图标尺寸、动效时长与缓动、字重与字距、间距刻度、层级阴影。
把 190 处硬编码分成「可归并 / 必须保留」两类，给出归并后的 token 清单。

### 你需要额外遵守

- 只做阶段 2。
- 不写组件代码（那是阶段 3）。
- 表格里的「影响组件」用组件名，不要写行号。

---

## 输入

- `app/src/main/assets/styles.css`（整份读）
- `docs/design/01-audit.md`

---

## 输出（分两个文件，避免单次输出过长）

### 文件 A：`docs/design/02-tokens.md`

必含四节：

1. **新增 token 表** —— `token 名 | 现值(纸感/账本) | 建议值 | 理由 | 影响组件`
   必须覆盖：图标尺寸、动效时长与缓动、字重与字距、间距刻度、层级阴影。
2. **硬编码归并规则** —— 190 处按「可归并 / 必须保留」两类说明判断标准，给出归并后的 token 清单。
3. **保留清单** —— 哪些色值必须硬编码（食材类目色、图表辅助线等），为什么不能用 token 表达。
4. **风险** —— 这次收敛可能带来的视觉回归点。

### 文件 B：`docs/design/02-mapping.csv`

逐条映射，表头固定：

```csv
line,current_value,kind,target_token,reason
```

`kind` 取值：color / space / radius / shadow / type / icon / motion。
如果条目过多导致单次输出接近上限，按 kind 分三批写，文件名追加 `-1/-2/-3`。
