# 26 · 记录页「训练」美术复盘与重做（2026-11-11 · 1.3.39）

> 触发：用户要求「模仿 opus5.5 模型的审美去判断记录-训练功能各个选项按钮含义是否明确、页面布局是否合理、
> 美术风格是否足够凝练、选项框便签堆叠是否美观？列出清单并逐一实现优化，并按 opus5.5 美术要求验收」。
>
> 本文件 = 判断 + 证据 + 清单 + 逐项落地 + 验收。截图见 `docs/design/art/training-20261111-*.png`。

## 一、一句话判断

这套界面**不是配色问题，是「纸」的比喻破了**：输入框被做成了「一块灰底板 + 一条深底边 + 12px 圆角」，
在 480 dpi 上底边的两个圆角端点悬在填充之外，每个字段都像**两张没对齐的便签叠在一起**；
同时整页有 6 个同权重的胶囊按钮、3 个同色角标、2 个「主行动」在抢注意力。
凝练不是再描一遍线，而是**把比喻修好、把权重排开、把重复删掉**。

## 四、验收（按 opus5.5 的判断，不是按规则）

1. **比喻是否成立**：现在每个字段是一张**便笺**（浅底 + 一圈发丝线），不再是两张纸叠着；
   动作名不套框，一行读作「1 卧推 → 3 组数 → 容量 1,160 kg」。纸感成立，账本/夜间各自成立。
2. **一屏一个主行动**：训练日志只有「保存训练」实心；今日顺序有清单时只有「全部加入今天的训练记录」实心；
   训练计划没有实心按钮（它的动作是「换一版 / 调整偏好」两个文本链接）。
3. **含义可用一句话说清**：模板／照上次练／常用动作／移除／加一组／容量／杠铃总重／休息 90s／清空今天的训练／保存训练
   —— 每个都答得出「按了会发生什么」；不再有「算一下负重」「组间休息」这种靠猜的词。
4. **重复信息已删**：「今天的状态」块、每行重复的「次/kg」、「动作 · 组 · 次 · 负重。」这句填充、
   周计划里 5 行连续的「休息」。
5. **数字可读**：容量 4,560 kg 是主数字；柱顶有值；组次重量等宽对齐；容量随组变化实时重算。

真机验证（1.3.39，1156×2510 / 480dpi，纸感）：

- 概览：`4,560 kg / 1 次 / — 目标 142 g`，柱顶 4,560，今日星期加粗。
- 计划：一行偏好摘要 + 一行「下一训练日」+ 合并后的周列表。
- 今日顺序：三行式，动作行右侧「换一个 · 记录」上下对齐；主按钮是「全部加入今天的训练记录」。
- 训练日志：模板行 + 常用动作 + 动作表；点「添加动作」出现带 1 组的新行并聚焦；
  点完成圆点变实心并开始 `休息 1:29 → 1:26` 倒计时；点空白组不产生数据。
- 皮肤：账本与夜间用同一套结构，动作名同样不套框（`/build/harness-night*.png` 为 Chrome DPR3 渲染对照）。

## 五、刻意没做（留到下一轮，不假装完成）

1. **周计划没有做成「7 格周条」**：现在只是把连续休息日合并成一行，仍是一条竖列表。
   真要「一眼看出一周的形状」，需要周条 + 点某天展开当天动作（JS 改动大于本轮）。
2. **今日顺序没有「拖拽排序」**：仍按模型给的顺序，只能改单行。
3. **训练日志没有做「训练时长 / 组间休息设置」**：休息固定 90s，没有按动作类型区分。
4. **概览柱状图仍无坐标轴与量纲**：只在柱顶给了数值，不做 y 轴。
5. **空态仍是「一条空白行」**：没有换成「今天还没记动作」的空态块（担心把「点进去就能写」的直接感拿掉）。
