# 26 · 记录页「训练」美术复盘与重做（2026-11-11 · 1.3.39）

> 触发：用户要求「模仿 opus5.5 模型的审美去判断记录-训练功能各个选项按钮含义是否明确、页面布局是否合理、
> 美术风格是否足够凝练、选项框便签堆叠是否美观？列出清单并逐一实现优化，并按 opus5.5 美术要求验收」。
>
> 本文件 = 判断 + 证据 + 清单 + 逐项落地 + 验收。截图见 `docs/design/art/training-20261111-*.png`。

## 一、一句话判断

这套界面**不是配色问题，是「纸」的比喻破了**：输入框被做成了「一块灰底板 + 一条深底边 + 12px 圆角」，
在 480 dpi 上底边的两个圆角端点悬在填充之外，每个字段都像**两张没对齐的便签叠在一起**；
同时整页有 6 个同权重的胶囊按钮、3 个同色角标、2 个「主行动」在抢注意力。
凝练不是再描一遍线，而是**把比喻修好、把权重排开、把重复删掉**。

## 四、验收（按 opus5.5 的判断，不是按规则）

1. **比喻是否成立**：现在每个字段是一张**便笺**（浅底 + 一圈发丝线），不再是两张纸叠着；
   动作名不套框，一行读作「1 卧推 → 3 组数 → 容量 1,160 kg」。纸感成立，账本/夜间各自成立。
2. **一屏一个主行动**：训练日志只有「保存训练」实心；今日顺序有清单时只有「全部加入今天的训练记录」实心；
   训练计划没有实心按钮（它的动作是「换一版 / 调整偏好」两个文本链接）。
3. **含义可用一句话说清**：模板／照上次练／常用动作／移除／加一组／容量／杠铃总重／休息 90s／清空今天的训练／保存训练
   —— 每个都答得出「按了会发生什么」；不再有「算一下负重」「组间休息」这种靠猜的词。
4. **重复信息已删**：「今天的状态」块、每行重复的「次/kg」、「动作 · 组 · 次 · 负重。」这句填充、
   周计划里 5 行连续的「休息」。
5. **数字可读**：容量 4,560 kg 是主数字；柱顶有值；组次重量等宽对齐；容量随组变化实时重算。

真机验证（1.3.39，1156×2510 / 480dpi，纸感）：

- 概览：`4,560 kg / 1 次 / — 目标 142 g`，柱顶 4,560，今日星期加粗。
- 计划：一行偏好摘要 + 一行「下一训练日 11-16 · 推 · 卧推」+ 合并后的周列表（11-12 → 15 · 休息 4 天，7 行剩 4 行）。
- 今日顺序：三行式，动作行右侧「换一个 · 记录」上下对齐；主按钮是「全部加入今天的训练记录」。
- 训练日志：模板行 + 常用动作 + 动作表；点「添加动作」出现带 1 组的新行并聚焦；
  点完成圆点变实心并开始 `休息 1:29 → 1:26` 倒计时；点空白组不产生数据。
- 皮肤：账本与夜间用同一套结构，动作名同样不套框（`/build/harness-night*.png` 为 Chrome DPR3 渲染对照）。

## 五、刻意没做（留到下一轮，不假装完成）

1. **周计划没有做成「7 格周条」**：现在只是把连续休息日合并成一行，仍是一条竖列表。
   真要「一眼看出一周的形状」，需要周条 + 点某天展开当天动作（JS 改动大于本轮）。
2. **今日顺序没有「拖拽排序」**：仍按模型给的顺序，只能改单行。
3. **训练日志没有做「训练时长 / 组间休息设置」**：休息固定 90s，没有按动作类型区分。
4. **概览柱状图仍无坐标轴与量纲**：只在柱顶给了数值，不做 y 轴。
5. **空态仍是「一条空白行」**：没有换成「今天还没记动作」的空态块（担心把「点进去就能写」的直接感拿掉）。

# 七、第二轮（2026-11-11 晚 · 1.3.44）美术优先于表格

> 用户原话：「继续，美术效果优先于表格结构」。
> 第一轮把「组/次/kg」做成了一张对齐的小表；这一轮把表拆掉，改成**手账式记组**，
> 并把周计划从「7 行文本」换成**7 格周条**。

## 7.1 判断

第一轮解决了「便签叠纸」和权重问题，但**训练日志仍然是一张表**：表头 + 两个等宽输入框 + 居中数字。
表格结构会让人先读「列」，再读「这一组练了什么」；而训练时你想读到的是**一行话**：
「第 1 组，10 次，60 公斤」。所以这一轮把数字放大成主角、单位只跟一次、表头删掉。

## 7.2 改了什么

| 项 | 改法 |
|---|---|
| 组行 | 从「表头 + 两个输入框」改为一行手账：`◯ 1  10 次 × 60 kg  ×`；数字 20px、单位 11px 跟在数字后、乘号淡化为分隔；删除按钮降为 17px 幽灵 × |
| 数字框 | `field-sizing: content` + `width:auto`，数字盒按内容伸缩，单位和数字之间不留空槽；不支持的 WebView 用 `@supports` 回落到固定宽度 |
| 聚焦 | 只长一条 2px 下划线 + 浅底，不换盒子、不改内边距（数字不左右跳） |
| 完成态 | 圆点实心 + 数字转灰；组号与圆点分列，扫一眼就知道练到第几组 |
| 周计划 | 7 行文本 → 7 格周条：星期 + 日号 + 一根 3px 短线（计划日半透明绿、已练实心、今天加深）；点某格在下方换一行详情（记录了什么 / 计划是什么 / 休息） |
| 计划卡语义 | **修了一个长期错位**：标题写「本周安排」，画的却是下周的计划（`startDate` = 下一个周一），所以计划日一根线都画不出来。现在周条与标题都按计划所在周，写作「下周安排 · 11-16 起」 |
| 删重复 | 去掉与偏好摘要重复的「每周 N 练」；去掉与周条详情重复的「下一训练日」小注 |

## 7.3 验收

- 真机（1.3.44）：
  - 训练日志：`◯ 1 10 次 × 60 kg`，容量实时 600 kg；点圆点变实心并开始 90s 休息（`docs/design/art/training-20261111-6-log.png`、`-7-set-done.png`）。
  - 周条：`16 17 18 19 20 21 22`，16/18/20 有短线；点 18 → 详情变「11-18 · 拉 · 高位下拉、坐姿划船、面拉」（`-5-weekstrip.png`）。
  - 账本 / 夜间：同一结构，数字不上底色（Chrome DPR3 对照）。
- 机械验收：`test-all` 61/61；`dev-loop 1.3.44/344` 全绿；aesthetic-audit 无新增违规。

## 7.4 仍然没做

1. 今日顺序的拖拽排序。
2. 组间休息按动作类型区分时长。
3. 概览柱状图的纵轴 / 量纲。
4. 训练日志空态块（仍是「一条空白行」，但占位符已改成「— 次 × — kg」）。

## 7.5 回滚

- 版本：1.3.44 / versionCode 344；APK `dist/qingheng-1.3.44.apk`（599 KB）。
- 代码：`git revert <本轮提交>`；只回滚视觉用 `git checkout <哈希> -- app/src/main/assets/styles.css`。

# 八、第三轮（2026-11-17 · 1.3.58）要点、理由、休息药丸、概览动效

> 用户原话：「完善下一个训练日（不同动作）的动作要点功能，完善为什么这样排功能（根据用户排训练动作时ai生成的内容确认），
> 使显示要点内容与实际用户需注意点匹配。让休息时间按钮出现在用户当前训练动作视野内（调整功能位置，且优化时间变动动效）。
> 优化训练概览视觉动画效果，以及下方文字说明。」

## 8.1 逐项改法

| 诉求 | 改法 | 落点 |
|---|---|---|
| 要点跟着「不同动作」走 | 旧版每个模板只有两条固定要点（推日永远是侧平举+RPE），和当天动作无关。改为按动作逐个取：①训练库模板要点里点名这个动作的那条（上斜/深蹲/引体）②以动作名开头的规则（「划船时过度肩胛后缩…」）③同分化标签且提到它的规则；都没有才补「做到接近力竭前停」。每条都带动作名 | `libraryCuesFor(day)` / `cueForExercise` / `cueTokens` |
| 要点排版 | 名称右对齐成 6em 一列、文字左对齐 → 三条要点读成一张清单，不是三段散文 | `.plan-cue-list` |
| 为什么这样排 | 先放「你排的那份清单为什么这么排」：读 `aiPlanStore(day)`，逐条列出 AI 当时给的理由；再放这一周的规则依据，并标清两边来源 | `aiPlanEntries` / `plan-why-ai` / `plan-why-lead` |
| 休息按钮进视野 | 从卡片底部工具行搬成固定小药丸（底栏上方 76px），24px 环形进度 + 剩余时间；只在「正在记组且保存按钮不在视野」或计时中显示；用 `rootMargin` 去掉底栏遮挡区的误判 | `#rest-dock` / `syncRestDock` / IntersectionObserver |
| 时间变动动效 | 环形进度 1s 线性收缩；秒数每秒一次 0.3s 小归位（`[data-tick]`），reduced-motion 全关 | `[data-tick]` / `.rest-ring-fill` |
| 概览动画 | 柱状图在「这周数据真的变了」时从 0 长到目标（40ms 错帧）；三个数字接 `[data-count]` 滚动（首帧不滚）；说明拆两行并给「比上周 ±%」 | `renderTrainingOverview` / `installCountRoll` |
| 概览说明 | 「本周 1 练 · 容量 X kg，比上周 +Y%」+「今天摄入 … / 蛋白 100 / 142 g」两行；没练时写「本周还没训练（上周 9,920 kg）」 | 同上 |

## 8.2 顺手修掉的两个真 bug

1. **每加一个动作多出一行空白、编号跳号**：`appendExerciseRow` 先建了一个 `.training-row` 外壳，又把 `exerciseRowHtml` 的完整行塞进它的 `innerHTML`，于是每行套行、编号从包装层算起（真机看到 1、3、4）。改成临时容器取 `firstElementChild`，并在增删后统一 `renumberExerciseRows()`。
2. **底部药丸在保存按钮附近不出现**：IntersectionObserver 把「被固定底栏盖住」的保存按钮算作可见，空转药丸被误判隐藏。观察器加 `rootMargin: '0px 0px -96px 0px'`，底栏遮挡区不算可见。

## 8.3 验收

- 真机 1.3.58：
  - 要点：展开「下一个训练日（推）的动作要点」，三条分别是杠铃卧推（握距决定练哪种关节活动）、上斜哑铃卧推（别把屁股往前挪）、侧平举（可以曲肘）——每条点名动作（`training-20261117-1-cues.png`）。
  - 休息药丸：记组视野内出现空转药丸「休息 90s」，点一下变实心、环形进度 + `休息 1:29`（`-2-rest-pill.png`、`-3-rest-running.png`）。
