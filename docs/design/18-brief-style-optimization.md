# 轻衡 · 视觉风格优化任务（风格主导，不是代码审计）

你是这个 App 的视觉设计主导。目标只有一个：让它看起来像一个有主张的品牌，而不是"被整理过的表单"。
仓库 D:\AI\health-android｜现版本 1.1.91｜测试 56/56。

## 已经成立的风格（不要推翻，只在其上加）
- 纸感底 + 衬线标题 + 苔绿强调；两套皮肤（paper / ledger）共用同一套语义色
- 字号 6 档 13/15/17/20/26/32；圆角 3 档 8/12/20
- 线语言三档：L1 --line 分区、L2 --line-strong 控件（3.36:1）、L3 focus-visible
- 图像语言三符号已入库：叶 icon-glyph-leaf / 天平 icon-glyph-balance / 环 icon-glyph-ring（24 网格、1.5px 圆头、单色）

## 做三件事，按顺序
### 1. 图形语言铺开（最能立刻改变气质）
把三个符号真正用起来：空态用叶 40px、加载用环 20px 匀速、完成用叶 24px + --ok。
同时定下"什么时候不用符号"——列 3 条禁用场景，避免装饰化。

### 2. 趋势图的信息设计（先给规格，再实现）
现在只有折线 + 周均值虚线，读不出"我在变好还是变差"。补三件：点按取数（44dp 热区）、目标区间带（12% 透明）、空态骨架（环 + 一句话）。
先写规格（每条 ≤3 行），确认后再动代码。

### 3. 今日页的视线顺序
现状：数字、按钮、解释文字挤在同一张卡，用户第一眼不知道该看哪。给出 before/after 截图，说明你调整了哪一层级。

## 硬规则（这些是别处踩过的坑）
1. **不要重定义已有维度**。例：能量环的绿环"始终满圈"代表 0–100% 目标，超出用棕红从同一起点覆盖；不要改成"0–300° 是目标、300–360° 给超出"——那会让"绿环多长"这个已建立的语义失效。要表达新维度，在原刻度上叠加标记，不要加长刻度。
2. 一段里最多一个"主数字"；同级数字必须同字号同字重。
3. 解释文字不与主行动同屏竞争：要么折叠、要么移出。
4. 两套皮肤改一处必须同时改另一处；账本改动只写在 [data-skin="ledger"]。
5. 新增颜色令牌：02-tokens.md 登记 + ledger 同名定义 + 两套皮肤令牌集相等，缺一测试红。
6. 改 fragment 后必须 tools\assemble-app.ps1，再 node tools\test-all.mjs 到 56/56。
7. 改测试断言先登记 docs/design/03-global-changes.md §5.1。
8. 恢复文件用 git show HEAD:<path> 经 node 写 Buffer；不要用 git checkout/restore（会被拦），也不要用 PowerShell 重定向（会写成 UTF-16）。

## 可以放宽（前提是更优，且要写清代价）
- 强调色一屏可多次：第二次起说明"为什么这里也需要"
- 动效上限 0.4s，叙事性入场可 0.6s，但必须保留 prefers-reduced-motion
- 允许引入字体 / 图表库 / 新页面：交付必须写代价（体积、皮肤一致性、维护）与回退方式

## 交付格式（固定）
每条任务三行：
```
判断: <现状哪里不对，一句>
改动: <文件:行 / 设计参数>
理由: <为什么这样更好，可验证>
```
外加：3 组 before/after 截图路径；一个"没做什么及原因"；测试与审计结果。

## 失败处理
同一目标两次仍红 → 停止，输出 `BLOCKED: <根因> + <需要什么>`。不要在红测试上反复试。
