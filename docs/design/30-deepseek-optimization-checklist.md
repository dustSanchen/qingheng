## 0. 给执行者的总指令

你正在优化 Android 本地优先健康记录 App「轻衡」，仓库是 `D:\AI\health-android`。

目标不是做一个综合健康平台，而是继续减少用户的三个问题：

1. 现在最值得做什么？
2. 今天记录得怎么样？
3. 下一步能不能直接完成，而不是再读一段建议？

先读根目录 `AGENTS.md`、`docs/design/00-START-HERE.md`，再按任务读取相关源码。不要整份读入 `styles.css`。

### 不可破坏的产品边界

- 本地优先、免费、无账号、无云同步；不新增统计 SDK、社区、排行榜、好友、会员、广告或连续打卡压力。
- 保留五页 IA：`今天 / 记录 / 问答 / 趋势 / 我的`；不增加第六个一级页面。
- AI 可选，使用用户自己的 OpenAI 兼容服务；没有网络、Key 或外发授权时，记录、目标计算、训练执行和本地计划仍须可用。
- 不诊断、不开处方，不给出疾病、药物或医疗结论；健康建议不夸大，不制造焦虑。
- 保留 `paper / ledger / night`，账本样式只能写在 `[data-skin="ledger"]` 作用域。
- 不恢复 2000 kcal 硬地板；目标与营养数字沿用现有 `GOAL_PRESETS`、目标计算和证据表。
- 应用文案不出现第三方品牌名，不写「加油」「坚持！」；不把记录缺失说成用户没做。
- 不新增依赖、CSS 框架或构建步骤；若确有必要，先停止并说明收益、体积和替代方案。
- 不覆盖、不清理、不回退用户已有改动；提交前检查实际 diff。

### 工程红线

- `app/src/main/assets/app.js` 是由 `app/src/fragments/*.fragment.js` 拼接的生成物，禁止手改。
- 修改片段后必须运行 `tools\assemble-app.ps1`。
- 版本号只通过 `tools\dev-loop.ps1` 同步，不手改；一个实现阶段只递增一次。
- 新逻辑优先抽成无副作用函数；时间、日期、状态作为参数传入，便于 Node 测试。
- 写入健康记录必须保持「草稿 → 确认 → 写入 → 反馈」；AI 不得直接落库，不得绕过确认。
- 一天仍只有一行测量、一行习惯；新增训练只追加，不覆盖当天动作。
- 每轮将真实执行、测试、未验证项追加到 `docs/design/RUNLOG-codex.md`；不把计划写成已完成。

## 1. 统一训练、休息日、未记录三种语义

### 已确认的问题

`renderDailyCheck()` 的训练缺口判断只看 `!h.training`，没有排除 `h.training === false`。因此明确记录的休息日，仍可能出现「补训练」类提示。另有计划采纳、清单完成、实际训练记录三个概念，不能互相冒充。

### 任务

- [x] 明确定义三态：
  - `undefined / null`：尚未记录，不等于没训练。
  - `false`：用户明确选择休息，不产生补练、漏练或训练评分压力。
  - `true`：已记录训练；是否完成计划仍由实际动作/执行状态判断。
- [x] `profile.training === 'none'` 的用户不生成训练催促、不显示训练计划任务、不把无训练记录算作缺点；保留其主动开启训练的设置入口。
- [x] 今日页、问答上下文、周报、趋势、通知使用同一训练语义；不要只修一个卡片而让周报继续误判。
- [x] 休息日文案使用「今天没有安排训练」「已记为休息」；未记录使用「尚未记录」。
- [x] 若当前 UI 缺少明确记休息日的方式，在现有日常习惯/训练记录流程补一个不显眼的入口；不训练用户不渲染该入口。
- [x] 修改当天饮食、体重、睡眠、饮水或计划时，不得意外把 `training:false` 改为 `true`。
- [x] 重复排课、重新打开页面、返回今天又离开时，不重复生成动作，不覆盖当天记录。
- [x] 不把「采纳计划」当成「完成训练」，不把「勾选清单」当成实际运动记录。
- [x] 保留 `1.4.70` 的排课只追加逻辑，不为满足默认每周次数给休息日强加训练。

### 必测用例

- [x] 无习惯记录：中性提示，不断言用户没做。
- [x] `training:false`：不出现补训练；热量、睡眠等其他记录仍正常。
- [x] `training:true` 且有动作：显示实际记录，不重复催促。

- [x] 非当天补记：今日页不拿旧记录冒充今天完成。
