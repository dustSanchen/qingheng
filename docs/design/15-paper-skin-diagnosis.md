# 15 · 纸感皮肤诊断（只取证，未改样式）

> 按 `14-design-thinking.md` 的模板写。本轮**没有改任何 CSS**，只做现状判定与归因。
> 证据：`build/records-paper-current-before.png`（23:14）、`records-paper-body-before.png`（23:18）、
> `records-paper-training-before.png`（23:16）、`docs/shots/paper/{today,record,trends,profile}.png`（14:02）。

## 一、现状判定

记录页（纸感）上同时存在**三档线宽/三种线型**：

| 位置 | 实际样式 | 行号 | 对纸底对比度 |
|---|---|---|---|
| 卡片、分段容器 | `1px solid var(--line)` #e4e9df | L860、L353 | **1.22:1** |
| 输入框 / 选择器 / 文本域 | `1px solid var(--line-strong)` #858e83 | L124 | **3.36:1** |
| 选中目标卡 | 边框换 accent + `box-shadow: 0 0 0 2px` | L96 | 2px 环叠加 |
| 校验错误态 | `border-color: danger` + `inset 0 0 0 1px` | L130 | 双线叠加 |
| 只读态 / 待办行 / 草稿 | `border-style: dashed` | L134、L299、L442 | 第三种线型 |

截图里肉眼可见的「输入框比其他框重」，不是错觉：**同一屏中 1.22:1 与 3.36:1 并存，亮度差 2.75 倍**。

## 二、归因（机制，不是感受）

1. **不是宽度问题**。两处都是 1px；在 3x 屏上渲染为同宽物理线。
2. **是「对比度跳变 + 线型分裂」**。容器线 1.22:1 几乎融进纸底，控件线 3.36:1 直接跳出来，
   视觉上形成「细框包着粗框」的错觉。
3. **叠加把 1px 变成 2–3px**。`aria-invalid`（L130）与选中目标卡（L96）都是「边框 + 1–2px 环」，
   屏幕上读作双线或粗线——这与账本皮肤「线条像素太粗」的投诉是**同一机制**。
4. **斜线态是第三条语言**。虚线同时出现在只读、待办、草稿三处，各自没有统一语义。

## 三、结构决策（下一轮才动手）

定义**线语言三档**，全局只允许这三档：

| 档位 | 用途 | 取值 | 依据 |
|---|---|---|---|
| L1 发丝 | 容器、卡片、分隔 | `1px var(--line)`（1.22:1） | 只承担分区，不承担识别 |
| L2 控件 | 可编辑控件边界 | `1px var(--line-strong)`（3.36:1） | WCAG 1.4.11 要求 3:1 |
| L3 焦点 | 仅 `:focus-visible` | `--ring-focus` 3px | 焦点是瞬时态，不参与静态层级 |

配套两条禁令：

- **禁止叠加**：任何元素不得同时拥有边框与 `box-shadow: inset/0 0 0 Npx` 形式的第二道线。
  错误态改为「L2 边框换 danger 色」，不再加内阴影（L130、L131 两处）。
- **虚线只保留一个语义**（只读），待办与草稿改用 L1 实线 + 标签区分（L299、L442）。

## 四、取舍

- **不把控件线降到 L1**：WCAG 1.4.11 要求可编辑控件边界 ≥3:1，`--line` 只有 1.22:1。
- **不改「填充替代描边」**：填充色 `--surface-soft` #f3f2ee 对纸底 #fffefa 只有 **1.08:1**，
  不能单独承担边界识别，改完反而不达标。
- **所以能动的只有两件事**：减少线型数量、消除叠加。这既降视觉噪音，又不牺牲可达性。

## 六、一句话

> 纸感不是「线更细」，而是**同屏只允许一套线语言**；现在它有三套，还叠了双线。
