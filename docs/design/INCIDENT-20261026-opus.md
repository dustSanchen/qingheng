## 根因（三条叠加）

1. **单价高**：Opus 6 折后输入 $2.4/M，是 Sonnet 的 2 倍、Haiku 的 40 倍。
2. **每步重发全量上下文**：agent 每调一次工具，系统提示 + 三份文档 + 77KB CSS + 全部历史重发一遍。
   上下文随步数线性增长，成本是平方级。
3. **缓存救不了**：实测该池子 **>200k token 时缓存关闭**（`cache_creation=0`），
   恰好是最贵的场景拿不到 90% 的折扣。

## 为什么没被提前拦住

- 我给的指令写的是「styles.css 整份读」——直接把最贵的路径铺好了。
- 当时的 `defaultMaxTokens` 是 32768，输出注定被截断，等于**花了钱还拿不到完整产物**。
- 没有任何预算护栏：DSH 侧没有单轮成本上限，池子侧也没有触发余额告警。

## 关于 `QUOTA 额度已用尽`

一条经验：**先看任务的输入有多大，再看任务的判断有多难。**
输入大 + 判断易 = 脚本 + 便宜模型；输入小 + 判断难 = 才轮到 Opus。
