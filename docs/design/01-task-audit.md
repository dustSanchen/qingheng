# 阶段 1 任务卡 · 多用户审计

先读 `docs/design/00-brief.md` 作为背景。背景里的硬约束与输出格式对你本轮全部有效。

---

## 本次任务

假设你是一个从没见过这个 App 的朋友，只看截图：
指出 5 个「会让人第一次用错或不敢点」的地方，按严重程度排序，每条注明证据（哪个元素/哪条规则）。
特别检查：空状态、按钮文案、目标切换后数字是否仍可读、不健身模式是否像残版。

### 你需要额外遵守

- 只做阶段 1。
- 不提解决方案，不给 CSS，不进入阶段 2。
- 全部结论必须来自截图，不得从代码反推「用户会不会点错」。

---

## 输入

只用 `docs/shots/` 下的截图：

- `docs/shots/paper/` —— 纸感皮肤：today / record / trends / profile
- `docs/shots/ledger/` —— 账本皮肤：同上四页
- `docs/shots/scenes/` —— `empty-today / empty-record / empty-trends / empty-profile`（全新空数据）、`onboarding`（引导首屏）
- 未采集：`no-training`（不健身模式）、`bulking`（增肌目标）——缺这两张时相关判断要写「需要 XX 截图才能判断」

截图统一为真机原图或 360×800。文件名即页面名，不要用 1.png / 2.png。

如果某个判断缺少对应截图，写「需要 XX 截图才能判断」，不要猜。

---

## 输出

写入 `docs/design/01-audit.md`，不要在对话里展开。

格式：5 条以内，按严重程度从高到低排列，每条包含三行：

```
1. 现象：……
   证据：……（哪个页面、哪个元素、哪条规则）
   后果：……（哪类用户会怎么用错 / 为什么不敢点）
```

---

## 停止条件

只做阶段 1。

完成后只回一行：`done，N 条已写入 docs/design/01-audit.md`。
