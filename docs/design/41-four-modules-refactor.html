① 今天首页：一条行动行，读数顺序先于动作

三项里两项已落地（行动行合一、分区切换移出卡片）。剩下两处：能量卡内部读数顺序、概况卡横滑改并列。

1行动行上移到宏量之前

  1. 改了什么：把 #today-action 从 #macro-summary 之后移到之前，卡内顺序变成「环 → 三入口 → 下一步 → 宏量 → 体检」。
  2. 为什么：这一行回答的是"接下来做什么"，宏量回答的是"现在怎么样"。先读结论再读明细，才不至于一屏都是数字却不知道点哪。
  3. 代价：行动行上移后，宏量三列离体检更近，视觉上会读成一组"数据区"——这正是我们想要的。

2概况卡：横滑 → 双卡并列

  1. 改了什么：.today-peek 从 overflow-x:auto 的横滑条改为 grid-template-columns:1fr 1fr，两卡各 ~168px。
  2. 为什么：横滑藏了第二张卡，首屏只看得见一张半，等于每次都要"发现一次手势"。两卡的信息量本来就各 3 个数字，收窄后仍可读；首屏也因此不再有隐藏内容。
  3. 需要守住：卡片最小宽度 156px，低于这个数「距目标 1.7 kg」会换行到第三行。文案因此压成「6.2 t · 较上周 +8%」这种两段式。

3分段切换：胶囊 → 文字分段

  1. 已做的：.fold-tabs 早在 1.5.25 就移出了卡片，成为下半区统一的分段控制器。
  2. 本次还差的：它仍是两枚带描边的胶囊，和下方卡片同形，读起来像"第二张卡"。改成文字 + 2px 下划线，只在选中项上出现强调色。
  3. 为什么：切换器是标签不是容器。去掉边框之后，"卡外分段"才真的读作分段，而不是"卡上又贴了一个小卡"。

状态与组件结构

  • 数据源：todayActionItems() → [{label,target,tone}]（agenda.primary + 2 secondary + 缺餐提示），todayActionCursor 管 1/N。
  • 渲染：renderTodayAction() 只改 #today-action-text / #today-action-count / bar.dataset.target，不重建 DOM。
  • 展开：#today-action-more → #day-brief-sheet（手动翻，不自动轮播）。
  • 本次只动顺序与两个选择器，状态机零改动，测试里的 today-action / today-peek 断言不受影响。

② 记录 → 身体：把方框换成发丝线

文案与维度归类已落地（识别按钮已是"识别体脂秤截图 / 照片"，睡眠已归习惯区）。剩下的是形态：三处内嵌盒子还在。

1今天体重：内嵌盒 → 大数字

  1. 改了什么：删掉 .body-weight 的描边 + 58% 底、24px → 31px，右侧留两行参照（上次 / 7 日 Δ），下方用 1px 发丝线收口。
  2. 为什么：这个卡只有一个数。盒子越大，越像"要填的表单"，而它其实只是一次跳转入口；数字放大后，视线先落在 64.2 而不是边框上。

2身体数据：2 列卡片 → 3 列裸数字

  1. 改了什么：体重 / 体脂率 / 肌肉量从 .metric-card（1px 边框 + 卡片底）改为一行三等分，竖发丝线分隔，数值 21px 半粗，下划线只在聚焦时出现。
  2. 为什么：这三项是同一维度的三次读数，不是三件独立的事。卡片网格把它们拆成了三个"盒子"，裸数字 + 竖线读作一张体检单；顺带省掉 2×10px 的间距和三圈边框。

③ 日常习惯：三张刻度卡 → 三行账本

这是四项里唯一还没做的一项。1.5.27 做的是"刻度卡 + 轨道 + 两胶囊"，四层结构；brief 要的是单行。两者冲突，这里按 brief 走，代价写在下面。

1四层压成一行

  1. 改了什么：.habit-meter（名称行 / 数字行 / 轨道 / 胶囊）→ .habit-row（左：名称 + 20px 值 + 单位；右：−/+ 26px 圆钮 + 最多两枚胶囊），三行各 44px。
  2. 为什么：轨道和胶囊是两种控件表达同一件事。一屏里三层控件（输入、拖拽、快捷）会让人先想"我该用哪个"，而这件事的正确成本是"一眼看到值、一下改成值"。
  3. 代价（必须说清）：拖到任意值的交互没有了。补偿是点数字直接调键盘输入（原本就支持），并且步进器支持 120ms 长按连加——手机上键入比拖拽更准。

2与 11-22 的"环形滑块"指令的关系

  1. 11-22 那轮要求"不要表单控件，实现环形滑块"，做成了刻度轨道 + 大数字；本轮 brief 要"轻量账本行"。
  2. 按最新需求走：轨道退场。环形滑块在 390px 宽度下每行至少占 88px 高，三行就吃掉了首屏之外的全部预算。
  3. 如果之后还要"可拖"，正确形态是点值弹出半屏大刻度，而不是常驻在行内——这一条留作可选，不塞进本轮。

3按钮收口

  1. 右上角只留 自定义快捷值（两步 sheet，已有）；底部只留 沿用昨日数据 + 保存日常习惯。
  2. 语义不变：步数/睡眠 = 设值，饮水 = 每次再加；胶囊标签按 k / L / h 缩写。

状态与组件结构

  • HABIT_DIAL：{steps:{step:500,digits:0},water:{step:250},sleep:{step:.5,digits:1}} —— 步进量、小数位、上下限都在这里。
  • readHabitQuick()/writeHabitQuick()：只认候选档位的两枚胶囊值；旧版"饮水总量"自动淘汰。
  • setMeter(key,value) 夹取 → 写 input.value → paintMeter()（只切 .is-empty 与 aria）；删除时 track/fill/thumb 三个引用一并去掉。
  • 数值不落库，保存时走 numericForm(form,['steps','water','sleep'])。

④ 记录 → 训练：删掉中间步骤

播种、工具栏、计划说明抽屉、每组勾选 + 休息倒计时都已落地。还差的是卡面残留的两个中间按钮：「把今天这节加入今日清单」和「把这周写进训练记录」。

1删两个中间按钮

  1. 改了什么：renderWeekPlan() 里的 adoptHtml（把今天这节加入今日清单）与 scheduleHtml（把这周写进训练记录）不再进卡面；"写入整周"降级进 #plan-sheet。
  2. 为什么：计划早就会自动播种成日志行（seedExercisesFromPlan，只写 DOM），所以"先点加入、再打勾"是纯多余的一步；留着它还会和自动播种打架——用户点了会以为要多存一份。
  3. 数据安全：播种只在当天日志为空时发生，清空后由 seedMutedFor(planNow) 抑制，不会把清掉的动作再播回来。

2说明只留一个入口

  1. 已落地：本周要求 / 这周怎么排的 / 训练负荷都 move 进 #plan-explain-body，卡面只剩周条。
  2. 本次补：卡上那句"两者不一致时以日志为准"也搬进抽屉（中间步骤删掉后，这句话就没有解释对象了）；单动作要点继续走动作名旁 ?。

3勾选即完成（已落地）

  1. 每组右侧 data-set-done：勾上 → markSessionStart() 记起点、startRestTimer(restSecondsFor(name)) 起倒计时、syncPlanDoneFromRow() 回写清单 done。
  2. 全组勾完且不止一个动作时收成一行 ✓ 名称 · N 组 · 容量 X kg，只收 CSS，组次仍在 DOM，保存与草稿照常读。

4顺手补一个状态口径：播种后别写"未记录"

  1. 现状：今天还没有落库记录时，计划会把动作播成可打卡行，但卡头 tag 仍是「未记录」——renderTrainingLog 只数已存动作。三行动作配「未记录」，会让人以为播种失败。
  2. 改法：有播种行、无落库行 → 「已排入 · N 个动作」；已落库 → 「模板 · N 个动作」。
  3. 为什么不说"待保存"：行还没动过，说"待保存"像在催；"已排入"只描述事实，与"勾完才落库"一致。

状态与组件结构

  • 四层写入边界（已定，不要混）：写库 /api/habits｜只写 aiPlanStore｜只改 DOM｜只动偏好。
  • 草稿：trainingDrafts（内存，按日期）→ 切页/切天不丢；form.dataset.templateTouched 决定模板是否被用户手动锁定。
  • 播种抑制：seedMutedFor(planNow) 按清单快照持久化，刷新不回填。
  • 本次只删两个渲染分支，状态机与保存链路零改动。

⑤ 结束训练弹窗：已达标，不必重做

逐动作明细、同模板容量对比、耗时、体感评级都在 trainingSaveDialogHtml() 里。这一屏只做确认，不列改动项。

为什么这屏不用改

  1. 汇总行：动作数 / 组数 / 容量 / 自重次数 / 有氧 —— 已在 parts 里拼好。
  2. 逐动作：.dialog-items 每条「动作名 · N 组 · 公斤数」（有氧显示距离/时长）。
  3. 对比：取同模板上一次训练的总容量，写"这次 ±X kg"；没有可比记录时整行不出现，不编数。
  4. 耗时默认值来自 sessionMinutesEstimate()（第一组勾选的时间起点），没有起点就留空。

要守住的边界

  • 对比只比同模板（推/拉/腿/其他），跨模板比容量没有意义。
  • 容量口径逐组 reps×weight，自重动作只记次数、不进公斤容量。
  • 弹窗里改耗时/体感 → 直接进保存请求，取消则一切不落库。
